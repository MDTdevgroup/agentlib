# Changes & Migration Guide: AgentLib 4.1.0

AgentLib 4.1.0 refactors the library's tool contract to cleanly decouple model-facing declarations (serializable metadata representation) from executable procedures (implementation thunks) and registry dispatch (`ToolLoader`). It also optimizes dispatch to constant-time $O(1)$ lookup, adds atomic batch registration, introduces higher-order runtime argument validation without external dependencies, and enforces cooperative cancellation.

---

## 1. Tool Authoring: `defineTool(declaration, implementation)`

In previous versions, tools were defined as single fused objects containing both schema metadata and executable code:

```javascript
// ❌ Legacy Fused Syntax (Still supported for backward compatibility)
toolLoader.addTool({
    name: 'get_weather',
    description: 'Get weather for a city',
    parameters: { type: 'object', properties: { city: { type: 'string' } } },
    func: async ({ city }) => weatherClient.get(city),
});
```

In 4.1.0, use `defineTool` to separate representation from procedure:

```javascript
// ✅ 4.1.0 Authoring Model
import { defineTool } from '@peebles-group/agentlib-js';

const getWeatherDeclaration = {
    type: 'function',
    name: 'get_weather',
    description: 'Get weather for a city',
    parameters: {
        type: 'object',
        properties: { city: { type: 'string' } },
        required: ['city'],
    },
};

async function getWeather(weatherClient, { city }, { signal } = {}) {
    signal?.throwIfAborted?.();
    return weatherClient.get(city, { signal });
}

export function createGetWeatherTool(weatherClient) {
    return defineTool(
        getWeatherDeclaration,
        (args, context) => getWeather(weatherClient, args, context)
    );
}
```

### Key Invariants
- `declaration` must be a clean, serializable object and **must not contain `func`**.
- `implementation` is an async function following `(args, context) => Promise<any>`.
- Keep trusted dependencies (database connections, HTTP clients, API keys) in factory parameters rather than merging them with model `args`.

## 2. Runtime Argument Validation: `withValidation`

Provider JSON Schemas guide model output, but they do not form a security boundary. AgentLib 4.1.0 introduces `withValidation(validateArgs, implementation)` to sanitize or validate model arguments before execution without requiring a heavy validator dependency in the library core:

```javascript
import { defineTool, withValidation } from '@peebles-group/agentlib-js';

function validateWeatherArgs(args) {
    if (!args || typeof args.city !== 'string' || !args.city.trim()) {
        throw new Error('Argument "city" must be a non-empty string');
    }
    return { city: args.city.trim() }; // Coerced / sanitized args
}

export function createGetWeatherTool(weatherClient) {
    return defineTool(
        getWeatherDeclaration,
        withValidation(
            validateWeatherArgs,
            (args, context) => getWeather(weatherClient, args, context)
        )
    );
}
```

- **Dual Validation Support**: Works with both parser-style validators (returning transformed data, e.g. Zod `schema.parse`) and assertion-style validators (returning `void`).
- **Structured Exceptions**: Validation failures throw a structured `Exception` with `type: 'ToolArgumentInvalid'`, preserving the original validation error as `cause`.
- **Cancellation Preserved**: The second `context` argument (including `signal`) is forwarded untouched.

---

## 3. Immutability of Projections in `getTools()`

> [!IMPORTANT]
> **Behavioral Change**: In earlier versions, `toolLoader.getTools()` returned references to the registry's stored internal objects. In 4.1.0, `getTools()` returns freshly reconstructed projections from normalized records.
>
> If your application mutated objects returned by `getTools()` expecting to modify internal registry state, that mutation will no longer take effect. Treat returned tool objects as immutable projections.

---

## 4. Metadata Consumers: `getToolDeclarations()`

Callers that only require serializable metadata (such as LLM provider adapters, system prompt snippets, telemetry tracers, and A2A agent cards) should call `toolLoader.getToolDeclarations()` instead of `getTools()`.

```javascript
// ✅ Returns serializable declarations only (no func property)
const declarations = toolLoader.getToolDeclarations();
```

This guarantees that executable JavaScript code is never serialized, logged, or passed to external model SDKs.

---

## 5. Constant-Time $O(1)$ Dispatch & Duplicate Detection

- **$O(1)$ Name Lookup**: `toolLoader.findTool(name)` now indexes both local and MCP tools into internal maps, replacing linear array scans on tool execution.
- **Local-First Precedence**: When listing tools via `getToolDeclarations()` or `getTools()`, local tools are listed before MCP tools.
- **Strict Uniqueness**: Tool names must be unique across the entire agent registry. Registering a tool name that already exists in local tools or on a connected MCP server throws an error immediately.

---

## 6. Atomic Batch Registration & MCP Rollback

- **Atomic `addTools(tools)`**: Pre-validates the entire batch before mutating the registry. If any tool is invalid or has a duplicate name (including duplicates within the batch itself), none of the tools in the batch are registered.
- **MCP Connection Rollback**: If an MCP server connects successfully but returns tools that conflict with already registered tools, `addMCPServer()` automatically disconnects and removes the server before throwing. If rollback also fails, an `AggregateError` is thrown preserving both causes.

---

## 7. Cooperative Cancellation (`context.signal`)

Every tool implementation receives `context` as its second parameter. Always accept `{ signal } = {}` and call `signal?.throwIfAborted?.()` before performing I/O:

```javascript
async function executeQuery(db, { query }, { signal } = {}) {
    signal?.throwIfAborted?.();
    return db.query(query, { signal });
}
```

Even if an underlying database or SDK driver lacks native cancellation support, checking `signal?.throwIfAborted?.()` ensures cooperative cancellation halts execution before expensive operations begin.

---

## 8. Recommended File Layout

Instead of maintaining a monolithic `tools.js` file, structure tools into focused modules and combine them in an explicit catalog:

```text
tools/
├── list-tables.js
├── get-schema.js
├── run-query.js
└── index.js           # Catalog combining factories
```

```javascript
// tools/index.js
import { createListTablesTool } from './list-tables.js';
import { createGetSchemaTool } from './get-schema.js';

export function createTools(dependencies) {
    return [
        createListTablesTool(dependencies.db),
        createGetSchemaTool(dependencies.db),
    ];
}
```
